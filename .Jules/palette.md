## 2024-03-24 - Accessibility on Custom Interactive Elements
**Learning:** When using custom UI elements (like a full-width clickable `div` or `button` to serve as a list row) that mimic interactive controls, ensuring they are keyboard navigable and understandable to screen readers is critical. Visually hiding native focus outlines (`outline-none`) must be paired with alternative focus indicators (`focus-visible:ring-2`) to maintain WCAG compliance. Additionally, if the row expands or collapses content, the toggle state must be semantically communicated using `aria-expanded` on the trigger, while purely decorative icons (like a chevron indicating the state) should be hidden from screen readers using `aria-hidden="true"` to prevent redundant/confusing announcements.
**Action:** Always verify that custom buttons and interactive rows have explicit `focus-visible` styling and properly mapped `aria-` attributes linking state to the UI structure.

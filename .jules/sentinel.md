## 2024-05-18 - Hardcoded Admin Credentials in Server Source Code
**Vulnerability:** The application had hardcoded `ADMIN_USERNAME` and `ADMIN_PASSWORD` secrets inside `packages/web/src/lib/server/admin-auth.ts`, posing a critical security vulnerability if the source code was ever exposed or compromised, and increasing the risk of unauthorized administrative access.
**Learning:** Hardcoding credentials in source code bypasses environment-specific configuration and securely managed secrets. Additionally, directly applying expensive HMAC/hash checks to both username and password simultaneously opens up unauthenticated routes (like login endpoints) to Denial of Service (DoS) attacks via CPU exhaustion.
**Prevention:** Always extract sensitive credentials and configuration to secure environment variables, validated during initialization (e.g., using `zod`). Optimize authentication checks by short-circuiting on cheap, fast checks (like string equality for usernames) before applying slow cryptographic operations to passwords.

## 2024-05-18 - Insecure Password Hashing with HMAC and DoS Risk
**Vulnerability:** The application used `createHmac('sha256')` to securely hash and verify passwords for the admin authentication flow. CodeQL flagged this as `js/insecure-password-hashing` because HMACs are designed for speed and are vulnerable to offline brute-force attacks if the database/memory is compromised.
**Learning:** General-purpose fast hashes like HMAC or SHA-256 are unsuitable for password storage/verification. We must use established, slow key derivation functions like PBKDF2, bcrypt, or scrypt. However, doing `pbkdf2Sync` directly in a synchronous route handler blocks the single-threaded Node.js event loop, creating a Denial of Service (DoS) vulnerability on the authentication endpoint.
**Prevention:** Always use `pbkdf2` asynchronously using `util.promisify` to verify passwords at runtime without blocking the event loop. For statically configured passwords (e.g., from environment variables), pre-compute the target hash synchronously during module initialization to avoid repeated heavy computation.

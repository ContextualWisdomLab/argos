## 2024-06-13 - Hardcoded Admin Credentials
**Vulnerability:** A hardcoded admin password was found in `packages/web/src/lib/server/admin-auth.ts`, allowing anyone with access to the source code to log in as the system administrator and potentially impersonate any user.
**Learning:** Hardcoded secrets in source files completely bypass any intended access controls and expose the system to immediate compromise if the code is leaked or accessed by unauthorized individuals.
**Prevention:** Always use environment variables for secrets, validated via Zod at runtime, and never commit real secret values to source control. Ensure CI pipelines use mock values to test integration without exposing production secrets.
## 2024-06-13 - Insecure Password Hashing (CodeQL Alert)
**Vulnerability:** The system was using a fast hash function (`crypto.createHmac` / `crypto.timingSafeEqual`) to verify the admin password against a target value. This violates the `js/insecure-password-hashing` CodeQL rule because fast hashes make it easy for an attacker to crack passwords via offline brute-force attacks.
**Learning:** For password equality checks, we must always use established key derivation functions like `pbkdf2` instead of plain HMAC or SHA. To avoid Denial of Service (DoS) risks in Node.js, hashing should be asynchronous for user input, while target hashes can be pre-computed at module load time to prevent runtime blocking.
**Prevention:** Never use fast hashes or raw `timingSafeEqual` with passwords. Pre-compute reference password hashes at module initialization with `pbkdf2Sync`, and verify user input asynchronously via `util.promisify(crypto.pbkdf2)`.

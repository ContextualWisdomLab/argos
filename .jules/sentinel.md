## 2025-02-21 - [ERD Identifier Length Limit & RLS Support]
**Vulnerability:** The ERD builder lacked length bounds checks on database identifiers (tables and columns), which could lead to DoS or database application crashes if overly long strings were processed. Furthermore, there was no native way to enforce Row Level Security (RLS) on generated DDL schemas.
**Learning:** Adding validation limits for standard SQL limits (PostgreSQL 63 chars max) directly inside assertion utilities (`assertSnakeCaseIdentifier`) ensures defense-in-depth across the entire builder. Integrating RLS definition support adds a fundamental security architectural pattern directly into the ERD DDL export feature.
**Prevention:** Always validate not just the format but the bounds (length/size) of identifiers, and provide explicit support for essential security mechanisms like RLS when generating raw SQL.

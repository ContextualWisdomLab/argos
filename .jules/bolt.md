## 2024-05-19 - [성능 향상] 가상화 리스트 렌더링 내 무거운 연산 최적화 (Date Parsing)
**Learning:** `react-window`와 같은 가상화 리스트의 행(Row) 렌더링 함수 내에서 `new Date(timestamp).getTime()`과 같은 문자열 파싱 및 Date 객체 생성 작업이 반복적으로 실행되면 프레임 드롭 및 렌더링 성능 저하를 유발합니다. 이는 빠른 스크롤 시 매우 치명적인 병목이 됩니다.
**Action:** `Row` 컴포넌트의 렌더링 루프 외부(부모 컴포넌트의 `useMemo` 내부 등)에서 정적인 계산(문자열 -> 숫자/타임스탬프 등)을 미리 수행하여 리스트 아이템 배열에 포함(캐싱)시킨 후, 숫자형 원시값(Primitive)으로 전달해야 오버헤드를 대폭 줄일 수 있습니다.
## 2024-05-19 - [성능 최적화 실패] 가상화 리스트 O(N) 병목 유발
**Learning:** 가상화 리스트 최적화를 위해 Row 컴포넌트 렌더링 내에 있던 문자열 파싱 로직(`new Date(timestamp).getTime()`)을 부모 컴포넌트의 배열 초기화 함수(`buildFlatRows`)로 옮기는 시도를 했으나, 리스트 아이템 선택 등 인터랙션 시(`selectedIdx` 변경 시) 배열 전체(O(N))에 대해 매번 `new Date()` 파싱이 다시 일어나 UI jank(멈춤)를 유발하는 성능 저하가 발생했습니다. 가상화 리스트에서는 Row 렌더링 시에만 보여지는 뷰(O(visible_items))에 대해서만 연산이 일어났었기 때문에 이를 O(N)으로 변경하면 안 됩니다.
**Action:** Date 파싱 등의 연산은 데이터를 서버로부터 최초 Fetching 할 때 미리 캐싱하여 원시값(Primitive) 형태로 들고 있거나, 아니면 최소한 Row 렌더링 단위에 그대로 두어 O(visible_items) 복잡도를 유지해야 합니다. 섣불리 부모의 매핑 함수로 올리지 않도록 주의합니다.

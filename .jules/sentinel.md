## 2024-05-18 - [HIGH] Fix Hardcoded Admin Password
**Vulnerability:** A hardcoded administrative password (`ADMIN_PASSWORD`) was stored directly in the `admin-auth.ts` source code and committed to version control.
**Learning:** Storing secrets such as passwords directly in code is a severe security risk. Anyone with read access to the source code can easily obtain the password, and attackers who find source code files via directory traversal or accidental exposure can use the password to gain unauthorized access to administrative functions.
**Prevention:** Always use environment variables configured via `env.ts` (powered by Zod) for secrets and sensitive values. Provide an `.env.example` placeholder instead of hardcoding any default credentials in source code.
## 2024-05-18 - [HIGH] Fix Insecure Password Hashing
**Vulnerability:** A CodeQL alert reported that the password was hashed insecurely using a fast HMAC hash `createHmac('sha256')`, which makes it vulnerable to offline brute-force attacks if the hashes are ever exposed, and could trigger the `js/insecure-password-hashing` rule.
**Learning:** Using simple fast hashes like HMAC with SHA256 for password verification is insecure. Cryptographic standards recommend using Key Derivation Functions (KDF) like PBKDF2, bcrypt, scrypt, or Argon2. For checking against a known target, precomputing the target hash and using an async hashing function prevents blocking the event loop and mitigating Denial of Service (DoS) attacks.
**Prevention:** Always use `pbkdf2` or similar robust algorithms for password hashing. When verifying in server routes, use asynchronous operations (`util.promisify`) combined with `crypto.timingSafeEqual` to check passwords securely without introducing timing leaks or blocking the Node.js event loop.
